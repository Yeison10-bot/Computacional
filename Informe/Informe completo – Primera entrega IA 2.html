1. Objetivo del proyecto

Esta entrega compara distintas técnicas de Machine Learning —árboles de decisión, Random Forest, KNN y K-means— aplicadas a dos problemas reales: predecir el cultivo más adecuado según las condiciones del suelo y clima (clasificación), y predecir la resistencia del concreto según su mezcla (regresión). El hilo conductor de todo el trabajo es el sobreajuste: en cada técnica se muestra cómo controlarlo y cómo se ve cuando ocurre.

Todo el proyecto corre desde una única interfaz interactiva (app.py, hecha con Streamlit), donde cada botón entrena el modelo correspondiente en vivo con los datos reales — nada viene precalculado.

3. Las bases de datos: cómo se usaron

El módulo preprocesamiento.py centraliza la carga de ambos datasets, para que el resto del código nunca tenga que leer un CSV directamente:

def cargar_crop():
    """Carga el dataset de clasificación de cultivos."""
    df = pd.read_csv(RUTA_CROP)
    X = df.drop(columns=["label"])   # X = las 7 variables predictoras
    y = df["label"]                  # y = la variable objetivo (el cultivo)
    return X, y, df

def cargar_concreto():
    """Carga el dataset de regresión de resistencia del concreto."""
    df = pd.read_csv(RUTA_CONCRETO)
    if "Row ID" in df.columns:
        df = df.drop(columns=["Row ID"])   # es solo un índice, no aporta info
    X = df.drop(columns=["csMPa"])
    y = df["csMPa"]                        # y = la resistencia (número continuo)
    return X, y, df

La convención X / y es estándar en Machine Learning: X (mayúscula) es la tabla de variables predictoras (una matriz), y (minúscula) es la columna que se quiere predecir (un vector).

4. Preprocesamiento

El preprocesamiento transforma las variables numéricas ANTES de entrenar, para que estén en una escala adecuada para el algoritmo que se va a usar.

def dividir_datos(X, y, test_size=0.2, random_state=42, estratificar=False):
    stratify = y if estratificar else None
    return train_test_split(X, y, test_size=test_size,
                             random_state=random_state, stratify=stratify)

def estandarizar(X_train, X_test):
    """Z-score: media 0, desviación estándar 1. Para KNN y K-means."""
    scaler = StandardScaler()
    X_train_esc = scaler.fit_transform(X_train)   # ajusta Y transforma el train
    X_test_esc = scaler.transform(X_test)         # SOLO transforma el test
    return X_train_esc, X_test_esc, scaler

Detalle importante del código: fit_transform se llama solo sobre X_train (calcula la media y desviación usando ÚNICAMENTE datos de entrenamiento), y luego transform (sin fit) se aplica al test. Si se ajustara el escalador con todos los datos (train+test juntos), habría "fuga de información" del test hacia el entrenamiento — un error común que infla artificialmente el desempeño.

TécnicaFórmulaSe usa en
Estandarización (Z-score)z = (x − media) / desviación KNN, K-means (dependen de distancias)
Escalado Min-Maxx' = (x − min) / (max − min) Alternativa que comprime a [0,1], mostrada en la interfaz para comparar
Sin escalar— Árboles y Random Forest (comparan valor vs. umbral, la escala no afecta)

📊 Gráfica: tabla antes/después de preprocesar (pestaña Preprocesamiento)

La interfaz muestra min / max / media / desviación de cada variable en 3 versiones (original, estandarizada, Min-Max) y las mismas 5 filas en las 3 versiones. Cómo leerla: en la versión estandarizada, la fila "mean" debería dar ≈0 y "std" ≈1 para todas las columnas, sin importar que rainfall llegue a 298 y ph no pase de 10 — eso demuestra visualmente que la estandarización iguala las escalas.

5. Métricas de evaluación

Estas métricas se calculan DESPUÉS de entrenar cada modelo, comparando lo que predijo contra la respuesta real del set de prueba (que el modelo nunca vio durante el entrenamiento).

5.1 Clasificación (cultivos)

MétricaPregunta que respondeCódigo (sklearn)
Accuracy¿Cuántas predicciones fueron correctas, en total? accuracy_score(y_test, pred)
PrecisionCuando el modelo predijo la clase X, ¿cuántas veces acertó? classification_report(y_test, pred)
RecallDe todos los casos que REALMENTE eran clase X, ¿cuántos encontró?
F1-scoreCombina precision y recall en un solo número

Fórmulas exactas (TP = verdaderos positivos, FP = falsos positivos, FN = falsos negativos, para una clase específica):

Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2 * (Precision * Recall) / (Precision + Recall)

5.2 Regresión (concreto)

MétricaQué mideFórmula
MAEError promedio, en las mismas unidades que csMPa (MPa) promedio(|real − predicho|)
RMSEComo MAE pero castiga más fuerte los errores grandes raíz(promedio((real − predicho)²))
R²Qué proporción de la variación logra explicar el modelo (1.0 = perfecto) 1 − (error del modelo / error de solo usar el promedio)

📊 Gráfica: Matriz de confusión

Es una tabla/heatmap donde las filas son la clase REAL y las columnas son lo que el modelo PREDIJO. La diagonal principal (de arriba-izquierda a abajo-derecha) son los aciertos; cualquier valor fuera de la diagonal es un error, y te dice exactamente con qué clase se confundió. Ejemplo real de este proyecto: en el árbol de cultivos, la fila "lentil" tiene la mayoría de sus casos en la columna "lentil" (aciertos), pero unos pocos caen en la columna "mothbeans" — el modelo confunde esas dos leguminosas porque tienen condiciones de suelo parecidas.

📊 Gráfica: Real vs. predicho (regresión)

Es el equivalente a la matriz de confusión pero para números continuos: cada punto es una muestra de prueba, el eje X es su valor real de csMPa y el eje Y es lo que predijo el modelo. Se traza una línea diagonal punteada de "predicción perfecta" — entre más pegados estén los puntos a esa línea, mejor el modelo. Puntos muy por encima de la línea significan que el modelo sobreestimó; muy por debajo, que subestimó.

6. Árboles de decisión

Un árbol de decisión aprende una secuencia de preguntas tipo "¿la variable X es menor o igual a un umbral?" que separan los datos en grupos cada vez más puros. Código central:

from sklearn.tree import DecisionTreeClassifier

modelo = DecisionTreeClassifier(
    max_depth=4,            # profundidad máxima (pre-poda)
    min_samples_leaf=5,     # mínimo de muestras por hoja (pre-poda)
    criterion="gini",       # o "entropy": cómo mide la impureza de un nodo
    random_state=42,        # semilla para que el resultado sea reproducible
)
modelo.fit(X_train, y_train)        # entrena
pred_test = modelo.predict(X_test)  # predice sobre datos nuevos

Poda: la pre-poda limita el crecimiento antes de entrenar (max_depth, min_samples_leaf); la post-poda deja crecer el árbol completo y luego recorta las ramas menos útiles con ccp_alpha:

path = arbol_completo.cost_complexity_pruning_path(X_train, y_train)
alphas = path.ccp_alphas          # niveles de poda posibles, de menor a mayor
arbol_podado = DecisionTreeClassifier(ccp_alpha=alphas[i], random_state=42)

📊 Gráfica: el árbol dibujado

Cada caja es un nodo. Si tiene una condición arriba (ej. X[6] rainfall ≤ 30.18), es un nodo interno: sigue la flecha "Sí" si la muestra cumple la condición, "No" si no. Cada caja muestra también la clase mayoritaria en ese nodo, el gini (0 = nodo perfectamente puro, todos son de la misma clase; más cercano a 1 = mezcla de varias clases) y n (cuántas muestras de entrenamiento cayeron ahí). El color de la caja también refleja la pureza: colores sólidos son nodos puros, colores más pálidos son nodos mezclados.

📊 Gráfica: efecto de la post-poda (ccp_alpha)

Eje X = nivel de poda (alpha), eje Y = accuracy. Dos líneas: train y test. Al principio (alpha bajo = poca poda) train suele estar muy por encima de test (sobreajuste). A medida que sube el alpha (más poda), train baja pero test puede subir o mantenerse — el mejor punto es donde test es más alto, aunque train haya bajado.

📊 Gráfica: comparación de los 3 modelos (tabla)

Compara, lado a lado, el árbol sin restricciones, el pre-podado y el de partición 70/30, mostrando % de train/test, registros exactos, tiempo de entrenamiento y accuracy train/test de cada uno — para ver de un vistazo cuál generaliza mejor y qué tan caro es entrenarlo.

7. Random Forest

Un Random Forest entrena muchos árboles distintos y decide por votación mayoritaria (en clasificación) o promedio (en regresión):

from sklearn.ensemble import RandomForestClassifier

modelo = RandomForestClassifier(
    n_estimators=491,   # cantidad de árboles (impar, para minimizar empates)
    random_state=42,
    n_jobs=-1,           # usa todos los núcleos del procesador en paralelo
    bootstrap=True,      # cada árbol se entrena con muestra aleatoria CON reemplazo
)

¿Por qué números impares (9, 49, 491)? Con un número par de árboles, dos clases podrían empatar exactamente en votos. En un problema de más de 2 clases (como los 22 cultivos), esto reduce pero no elimina el riesgo de empate entre dos clases minoritarias — por eso también se define una regla de desempate basada en predict_proba (la probabilidad promedio del bosque), en vez de solo contar votos.

📊 Gráfica: árboles vs. tiempo vs. accuracy

Dos ejes Y sobre el mismo eje X (número de árboles, en escala logarítmica): la línea naranja es el tiempo de entrenamiento (sube casi en línea recta), la línea azul es el accuracy en test. Lo que hay que buscar: el accuracy típicamente sube rápido de 9 a 49 árboles y luego se aplana — de 49 a 491 el tiempo se dispara pero el accuracy casi no mejora, lo que demuestra que "más árboles" no siempre vale la pena.

📊 Gráfica: importancia de variables

Barras — cada barra es una variable, la altura es cuánto contribuyó (en promedio, entre todos los árboles del bosque) a reducir la impureza. Las variables con barras más altas son las que el modelo considera más determinantes para decidir la clase.

📊 Gráfica: árbol individual dentro del bosque

Es literalmente uno de los N árboles del bosque, dibujado igual que en la sección de Árboles. Cambiar el número del árbol muestra cómo cada uno terminó distinto, aunque entrenaron sobre la misma base de datos — evidencia visual directa del bootstrap (cada árbol vio una muestra aleatoria distinta).

8. Regresión (árboles y Random Forest sobre concreto)

Mismo código que clasificación, pero con las versiones de regresión:

from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor

modelo = DecisionTreeRegressor(max_depth=6, random_state=42)
modelo.fit(X_train, y_train)
pred = modelo.predict(X_test)   # devuelve NÚMEROS, no clases

mae = mean_absolute_error(y_test, pred)
rmse = (mean_squared_error(y_test, pred)) ** 0.5
r2 = r2_score(y_test, pred)

La diferencia conceptual: en cada nodo, en vez de medir "impureza de clase" (gini), se minimiza la varianza dentro del grupo resultante; la predicción de una hoja es el promedio de csMPa de las muestras que caen ahí. Por eso en el árbol dibujado cada hoja muestra valor = X.XX en vez de una clase.

Las gráficas de "árboles vs. tiempo vs. accuracy" se repiten aquí pero mostrando R² en vez de accuracy, y la matriz de confusión se reemplaza por el gráfico de real vs. predicho descrito en la sección de métricas.

9. KNN (K vecinos más cercanos)

from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score

modelo = KNeighborsClassifier(n_neighbors=5, weights="distance")
modelo.fit(X_train_esc, y_train)     # "entrenar" = solo guardar los datos
pred = modelo.predict(X_test_esc)    # predecir = comparar contra TODO lo guardado

KNN es distinto a todo lo anterior: no aprende una estructura fija, sino que guarda todos los datos y, al predecir un punto nuevo, busca sus K vecinos más cercanos (por distancia euclidiana) y vota la clase mayoritaria entre ellos. Por eso requiere datos estandarizados (sección de preprocesamiento) — de lo contrario, una variable con rango grande como rainfall dominaría el cálculo de distancia.

Para elegir K se usa validación cruzada (cross_val_score, que entrena y evalúa el modelo varias veces con distintos subconjuntos de los datos de entrenamiento, para obtener una estimación más confiable que una sola partición):

for k in range(1, 26):
    modelo = KNeighborsClassifier(n_neighbors=k)
    score = cross_val_score(modelo, X_train_esc, y_train, cv=5).mean()

📊 Gráfica: K vs. accuracy (validación cruzada)

Eje X = valor de K probado (1 a 25), eje Y = accuracy promedio de validación cruzada. Cómo leerla: normalmente empieza alta en K bajo, puede bajar un poco y luego decrece progresivamente en K muy altos (subajuste: promedia con vecinos demasiado lejanos/irrelevantes). El punto elegido (marcado con línea verde) es el mejor equilibrio. En este proyecto, K=1 resultó ganador porque el dataset de cultivos tiene clases muy bien separadas — poco riesgo de "memorizar ruido" porque casi no hay ruido.

📊 Gráfica: comparación de ponderaciones

Tabla comparando accuracy con weights='uniform' (todos los vecinos votan igual) vs. 'distance' (los más cercanos pesan más) vs. variables ponderadas manualmente por su importancia (usando un Random Forest como referencia). Sirve para ver si darle más peso a ciertas variables (como rainfall o humidity, que resultaron ser las más discriminantes) mejora el resultado.

10. Clustering (K-means)

from sklearn.cluster import KMeans

# Nótese: y (la columna 'label') NO se usa aquí, solo X
modelo = KMeans(n_clusters=22, random_state=42, n_init=10)
clusters = modelo.fit_predict(X_esc)   # asigna cada fila a un cluster (0, 1, 2...)

K-means es aprendizaje no supervisado: recibe solo las variables numéricas (sin label) y agrupa por similitud, sin saber qué cultivo es cada uno. La columna label se usa DESPUÉS, únicamente para evaluar qué tan bien esos grupos coinciden con los cultivos reales.

El algoritmo itera 4 pasos: (1) elige K centroides iniciales, (2) asigna cada punto al centroide más cercano, (3) recalcula cada centroide como el promedio de los puntos que le tocaron, (4) repite 2-3 hasta que los centroides casi no se muevan (convergencia).

📊 Gráfica: codo, silueta y Davies-Bouldin (3 técnicas para elegir K)

Codo (inercia): eje Y = suma de distancias al cuadrado de cada punto a su centroide; baja siempre que K sube, se busca el "codo" donde deja de bajar bruscamente. Silueta: va de -1 a 1, más alto es mejor (cada punto se parece más a su propio cluster que al más cercano); se busca el K que la maximiza. Davies-Bouldin: más bajo es mejor (compara qué tan compactos son los clusters contra qué tan separados están entre sí). En este proyecto, las 3 técnicas sugieren K bajo (~2), muy lejos de las 22 clases reales — evidencia de que varios cultivos comparten condiciones de suelo/clima parecidas.

📊 Gráfica: convergencia de los centroides

Eje X = número de iteración, eje Y = cuánto se movieron los centroides respecto a la iteración anterior. Debe ir bajando hasta acercarse a cero — eso significa que el algoritmo ya encontró una posición estable para los centroides (convergió).

📊 Gráfica: matriz de confusión (clusters vs. clases reales)

Igual que la matriz de confusión de clasificación, pero las "predicciones" son los clusters (después de emparejar cada cluster con su clase real mayoritaria, usando el algoritmo húngaro para el emparejamiento óptimo). Con K=22, se logró un 75% de coincidencia con los cultivos reales — sorprendentemente bueno para un método que nunca vio las etiquetas.

11. Comparación con ruido: sobreajuste vs. buen ajuste vs. subajuste

Con el dataset de cultivos (limpio, clases bien separadas) un árbol sin restricciones casi no sobreajusta — no porque no pueda, sino porque no hay ruido que memorizar. Para verlo de verdad, se inyecta ruido artificial en las etiquetas de ENTRENAMIENTO (el test queda limpio):

rng = np.random.RandomState(semilla)
n_ruido = int(len(y_train) * porcentaje_ruido / 100)
idx_ruido = rng.choice(len(y_train), size=n_ruido, replace=False)
for idx in idx_ruido:
    y_train_ruidoso[idx] = rng.choice([clases distintas a la original])

📊 Gráfica: barras train vs. test por estrategia

Cada estrategia tiene dos barras: café (train con ruido) y verde (test limpio). Entre más grande la barra café comparada con la verde, más está memorizando ruido en vez de generalizar — eso ES el sobreajuste, visualmente. El Random Forest, aunque cada uno de sus 200 árboles individuales crece sin restricción (como el "sobreajustado"), casi no muestra ese hueco: promediar muchos árboles entrenados con submuestras distintas diluye el efecto del ruido — esa es la razón concreta por la que un bosque resiste mejor el sobreajuste que un solo árbol.

13. Conclusiones

  • El preprocesamiento correcto depende del modelo: árboles/RF no necesitan escalado, KNN/K-means sí (estandarización).
  • Un árbol sin restricciones sobre datos limpios no sobreajusta por sí solo — el sobreajuste aparece cuando hay ruido/casos atípicos que el árbol memoriza en vez de generalizar, y se controla con poda.
  • Random Forest reduce el sobreajuste frente a un árbol individual gracias al bootstrap (cada árbol ve una muestra distinta) y a promediar muchos árboles — se demostró numéricamente comparando el mismo dataset ruidoso.
  • KNN y K-means dependen completamente de la escala de las variables (por eso necesitan estandarización) y de elegir bien sus hiperparámetros (K), para lo cual se usan validación cruzada (KNN) o métricas de calidad de clusters (K-means).
  • Las métricas de evaluación deben elegirse según el tipo de problema: accuracy/precision/ recall/F1/matriz de confusión para clasificación; MAE/RMSE/R² para regresión.
